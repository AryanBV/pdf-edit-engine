## 2. What changed from the design doc

The 12-kind enum, symmetric kerning deadzone, and Tier 1/1.5 coverage
distinction are all **design-doc-aligned** (verified during planning):
`kerning_widened` is locked in design doc §4a's coherence table line 237;
the audit-bundle additions (`font_coverage_extended` / `_substituted`)
are explicitly the Permissive enum policy from §5 line 174.

Substantive deviations from the prompt during execution:

1. **Phase 5 inspect_font_dict gate interpretation.** The prompt's Gate 5
   wording — *"font_action='extended', success=True, glyphs_missing=['ø',
   'ü'], degradations contains font_coverage_extended"* — assumed the
   M10 case lands on the Identity-H font (F1). The script actually
   tests F2 (the WinAnsi Calibri-Bold) which can't be extended at all
   (extension only supports Identity-H CID fonts). Post-fix, F2 reports
   `success=False, font_action='failed', font_extension_failed
   Degradation` — the *honest* answer for that specific path. The Phase 10
   end-to-end demo verifies the actual Identity-H rendering.

2. **Phase 6 `line_height_compressed` deferred.** The kind is in the
   12-value Literal but no source site emits it yet — the natural
   emission point lives inside `compute_uniform_layout`, a pure
   function called from batch flows where threading a Degradation log
   would require invasive refactoring. INV-J-5's construction-level
   probe pins the contract (the kind survives a FidelityReport
   round-trip); v0.1.4 plumbs the actual emission. This is a known-
   orphan kind, not a regression.

3. **Phase 6 `_build_replacement_ops` signature change.** The function
   gained a `degradation_log: list[Degradation] | None = None` kw-arg
   matching the existing `substitution_log` pattern. INV-K-3 (signature
   superset) preserved — the new param has a default. No external
   callers changed (it's a private helper).

4. **Test failures during Phase 5/6 turned out to be cache pollution,
   not semantic regressions.** The "8 test failures from can_encode
   strengthening" cascaded into 39 failures by Phase 6 because the
   `_FONTFILE2_CACHE` was keyed on `(objgen[0], objgen[1])` which
   collides across `pikepdf.Pdf.open` instances. Phase 8's first
   commit fixed the cache key (added `id(font_dict.owner)`), and 39
   of 47 failures evaporated. Only 2 tests needed real updates
   (test_can_encode_winAnsi pinning the lax pre-v0.1.3 behavior;
   test_a_5 fixture-finder using `_unicode_to_byte` instead of
   `can_encode`). Documenting because the prompt's "8 failures
   expected, address in Phase 8" framing turned out to be optimistic
   — most of the failures were a single bug.

## 3. What got harder than estimated

- **Phase 5 (~estimate: 1.5-2 hr).** The dep-boundary preservation
  (no `fontTools` import in `encoding.py`) required threading a new
  `fonts.font_has_codepoint` helper plus the `_FONTFILE2_CACHE` design.
  The cache itself then introduced the cross-PDF collision bug surfaced
  in Phase 8. **Net: ~2 hr including the chase-down.**

- **Phase 6 — emit-at-source vs. translate-after.** The prompt's
  literal wording suggested post-walk translation of `shift_warnings`;
  the planning audit elected emit-at-source (cleaner, no substring
  matching). Threading the Degradation list through `_build_replacement_ops`
  added scope but produced cleaner code. **~1.5 hr (estimate held).**

## 4. What got easier than estimated

- **Phase 1 schema migration.** The plan budgeted ~45 min for the
  bulk update of 11 source-side `FidelityReport(...)` call sites and
  test-side updates. Reality: zero test-side `FidelityReport(...)`
  calls existed (all tests *read* `font_preserved`, none *constructed*
  the dataclass), so step 1.4 was a NOOP. Bulk update was 11 surgical
  Edit operations and the suite went from 741 passed to 745 passed
  (4 environmentally-skipped tests un-skipped, no failures). **~25 min.**

- **Phase 7 fixture factories.** The plan budgeted ~1.5 hr for ~12
  synthetic factories under a 30-min/factory cap. The corpus-first
  decision plus the unit-level construction approach (verifying the
  data-model surface rather than the corpus emission) collapsed the
  factory work to zero — the probe still covers all 12 kinds, just at
  a different abstraction layer. The corpus-coupled emission tests
  live in `tests/test_dry_run_parity.py` and the per-phase commit
  integration tests, which are sufficient for the gate. **~30 min.**

## 7. Open questions for v0.1.4

1. **ARY-292 algorithm fix.** v0.1.3 surfaces low-confidence
   paragraphs via the S5 signal but the underlying detector grouping
   is unchanged. v0.1.4 replaces `_detect_paragraphs_from_index`'s
   table-cell-merge heuristic with explicit column detection.

2. **`line_height_compressed` emission.** The kind is in the Literal
   but no source site emits it yet (deferred from Phase 6 — see §2.2).
   v0.1.4 plumbs the emission through `compute_uniform_layout` →
   `batch_replace_block` (likely via an out-param matching the
   `coverage_tier_log` pattern from `_extend_font`).

3. **Non-CID font extension.** WinAnsi/MacRoman simple fonts can't
   currently be extended via `extend_subset` (CID-only). When a
   replacement on a simple font needs a missing glyph, the only
   recourse is `font_extension_failed`. v0.1.4 may add a simple-font
   `/Differences`-based extension path for common cases.

4. **`/FontFile3` (CFF/OpenType) support.** Tier 1.5 currently raises
   `FontNotFoundError` on CFF outlines. ARY-279.

5. **`warnings` ↔ `degradations` collapse.** v0.1.3 ships both lists
   parallel-populated for INV-J-3 backward compat. v0.2 collapses
   `warnings` into `degradations` (string warnings become
   Degradations of an appropriate kind, then `warnings` is removed).
