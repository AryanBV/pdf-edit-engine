## §1 Kerning algorithm decision

**Locked decision: Algorithm A — `Tz` horizontal text-space scaling — at all
deltas. No refusal threshold; clamp to a minimum readable factor only at
extreme compression.**

### Empirical evidence

The two candidates were implemented as standalone scripts under
`experiments/v013_kerning_compare/`:

- **Algo A** (`algo_a_tz_scaling.py`): emits the replacement as a flat string
  wrapped by `Tz factor` / `Tz 100` operators, where
  `factor = 100 × original_width / replacement_width`.
- **Algo B** (`algo_b_uncapped_kerning.py`): a faithful copy of v0.1.2
  `surgeon._encode_with_kerning` lines 281–289 with the line-271
  `> 0.5 × original_fu` cap removed; proportional per-glyph kerning runs at any
  delta.

Both were applied to `experiments/v013_kerning_compare/input.pdf` (the M10 SOW,
copied from `pdf-marketing/m10-launch/sow.pdf`) at three replacements:

| label | replacement | actual delta | Algo A `Tz` factor | Algo A overlaps | Algo B overlaps |
|---|---|---|---|---|---|
| d15 | `Sarah Chen` → `Sarah Cohen` | +11.5% | 89.7% | 75 | 77 |
| d25 | `Sarah Chen` → `Sarah Chenoa` | +22.0% | 81.9% | 79 | 80 |
| d40 | `Sarah Chen` → `Sarah Chen Smith` | +56.4% | 63.9% | 80 | **87** |

Visual evidence: `experiments/v013_kerning_compare/comparison.png` — at d25 Algo
B already shows visible inter-glyph compression on "Sarah Chenoa"; at d40 Algo B
produces "SarahChenSmith"-style glyph collisions, while Algo A renders as
horizontally-compressed but legible Calibri. Quantitative: collision-count delta
across d15→d40 is +5 for Algo A vs +10 for Algo B (`collision_count.py`).

### Verification gates

- **Gate (a) — M10 (WinAnsi): inconclusive on the kerning variable alone.**
  Both Algo A and the v0.1.2 baseline produce visibly missing ø/ü glyphs in
  `m10_verification.png`. The engine returns `font_action="kept"`
  (`extend_subset` not invoked), but the embedded Calibri subset's `/Widths`
  range and `/FontFile2` glyph slots are missing the high-byte chars.
  This is a **separate font-extension bug surfaced during the experiment** —
  out of scope for v0.1.3 kerning algorithm choice. The kerning decision is
  grounded in the d15/d25/d40 ASCII evidence (which isolates the kerning
  variable from font extension); the M10 result establishes Algo A's
  `Tz` factor for the +13.5% delta of `Sarah Chen → Søren Müller` would be
  88.1% (mild compression, well within Algo A's safe range).

- **Gate (b) — Identity-H regression: PASS.** Applied Algo A to
  `tests/corpus/cidfont_synthetic.pdf` with `Software Engineer → Senior
  Software Engineer` (~+40% delta). Text equality with v0.1.2 baseline
  confirmed by `verify_identity_h_text.py`:
  `baseline_text == algo_a_text` returns `True`. `identity_h_regression.png`
  shows pixel-equivalent rendering. Algo A does not regress the engine's
  primary encoding path.

### Refusal policy

No refusal threshold for v0.1.3. `Tz` scaling preserves glyph shape regardless
of factor; readability degrades only at extreme compression
(`Tz < 50` → glyphs scaled below half-width). Code MAY emit
`Degradation(kind="kerning_compressed", severity="warning",
detail=f"Tz {factor:.0f}%")` whenever `factor < 95` so callers see compression
events as data, but the edit always succeeds. **Refusal-on-degradation is the
agent's choice via gating on `degradations`, not the engine's policy.**

## §2 Detector signal design

**Locked signal: `S5 = (paragraph_width / page_width >= 0.5) AND
(avg_row_stub_coverage < 0.55) AND (x_cluster_count >= 2)`. Emits
`Degradation(kind="paragraph_detection_low_confidence", severity="info")` per
matched paragraph.**

### Step 0 — fixture coverage

`tests/corpus/` inventory (15 PDFs):

| Generator | Files used | Table-cell coverage |
|---|---|---|
| Word | `experiments/v013_kerning_compare/input.pdf` (SOW copy) | YES — Deliverables 4×2, Fees 3×2, signature blocks |
| reportlab | `tests/corpus/reportlab_table.pdf` | YES — 3×3 quarterly table |
| Chrome | `tests/corpus/chrome_webpage.pdf` | YES — multi-element stat-cards |

| pikepdf-synthetic | `pikepdf_synthetic.pdf`, `cidfont_synthetic.pdf` | NO; synthetic construction NOT performed within 20-min cap (rationale below) |

Per Phase 2 Step 0 hard cap, pikepdf-synthetic table fixture construction was
**deferred**. Three of four required corpora cover the table-merge case
adequately, the fourth being self-generated and known not to exhibit the
pattern; calibration is **partial on pikepdf-synthetic, full elsewhere**.

### Steps 1–3 — content-stream inspection

Output: `experiments/v013_detector_calibration/inspection.txt`. Key findings:

- **SOW (Word):** 308 `re` (rectangle) operators, 60 `BMC`/`BDC` marked-content
  blocks (mostly `/Span`, `/Artifact`). Tables are drawn as rectangles AND
  the cell-text is positioned by `Tm` with no per-cell marker — the existing
  `_detect_paragraphs_from_index` cannot distinguish table rows from natural
  multi-line flow.
- **reportlab_table:** 9 `S` (line-stroke) operators, 1 `re`, no marked-content.
  Same pattern — bare text positioned at cell coords with stroke gridlines
  unrelated to text grouping.
- **chrome_webpage:** 84 `re`, 44 `f`, 7 `S`. BDC tags include `/H1`, `/H2`,
  `/Code`, `/Form` — semantic but not cell-specific.
- **resume:** 234 `re`, 71 BDC. 119 paragraphs detected; multi-column heavy.

**Cell delineation is generator-specific and unreliable.** Pure
content-stream-derived signals (text-block position clustering, line-coverage
ratios) are the only universal mechanism. The signal locked below uses these.

### Step 4 — labeled corpus

`labels.md` documents 11 confirmed TRIGGER cases (8 in SOW, 2 in reportlab) and
16 confirmed OK cases. Implicit OK denominator: ~230 paragraphs across the 5
fixtures, all visually verified non-merge.

### Step 5 — signal evaluation

Per `fpr_table.md`:

| Signal | TP | FP (confirmed) | FP (implicit) | FN | aggregate FPR | recall |
|---|---|---|---|---|---|---|
| C1: width-only | 7 | 1 | 4 | 4 | ~2% | 64% |
| C2: stub-only | 7 | 0 | ~5 | 4 | ~2% | 64% |
| C3: column-only | 9 | 4 | many | 2 | >15% | 82% |
| **S4** (analysis-original) | 3 | 0 | 0 | 8 | **0%** | 27% |
| **S5** (locked) | 7 | 0 | 0 | 4 | **0%** | **64%** |

S5 = `S1 ≥ 0.5 AND S2 < 0.55 AND S3 ≥ 2`. Catches all 4-cell+ table merges
AND 2-cell merges with low coverage; misses 4 borderline 2-cell cases where
each "cell" is itself wide content (high S2). FPR is 0% — comfortably under
the 5% bar; agents will not see noise.

### Locked threshold values

| Constant | Value |
|---|---|
| `S1_MIN` (width ratio) | 0.50 |
| `S2_MAX` (stub coverage) | 0.55 |
| `S3_MIN` (x-cluster count) | 2 |
| `Y_BUCKET` (line clustering, pt) | 4.0 |
| `X_TOL` (cluster tolerance, pt) | 8.0 |

The implementation lives in a new helper inside `reflow.py` adjacent to
`_detect_paragraphs_from_index`; it does not change the detector's grouping
behavior. It runs as a post-pass on each paragraph the detector emits, and
appends `Degradation(kind="paragraph_detection_low_confidence",
severity="info", detail=f"width={s1:.2f},cov={s2:.2f},cols={s3}")` to the
returned `EditResult` for any reflow whose paragraph triggers S5.

**No escalation needed.** The architecture analysis offered (a) bundle
ARY-292's full algorithm fix or (b) defer to v0.2 if no signal hit
<5% FPR. S5 hits **0% FPR** — neither escalation applies. ARY-292's algorithm
fix (replacing the detector logic, not just surfacing) is appropriate v0.1.4
work; v0.1.3 surfaces what the existing detector misgroups, and that signal
is now provably reliable.

## §4 `font_preserved` truth function and `dry_run` contract

### 4a. `FONT_AFFECTING_KINDS`

```python
FONT_AFFECTING_KINDS: frozenset[str] = frozenset({
    "heading_font_dropped",
    "marker_font_dropped",
    "font_extension_failed",
})
```

| Kind | In set? | Reason |
|---|---|---|
| `kerning_compressed` | NO | Glyph identity preserved; only inter-glyph spacing changes. README will explicitly redirect: *`degradations` is the visual-fidelity gate, not `font_preserved`.* |
| `kerning_widened` | NO | Same as above |
| `heading_font_dropped` | **YES** | Font literally swapped |
| `marker_font_dropped` | **YES** | Font literally swapped |
| `line_height_compressed` | NO | Layout, not font |
| `overflow_shift_clamped` | NO | Layout, not font |
| `overflow_shift_suppressed` | NO | Layout, not font |
| `reflow_aborted_to_simple` | NO | Layout fallback; font intact |
| `font_extension_failed` | **YES** | No font preserved on failure path |
| `paragraph_detection_low_confidence` | NO | Detection metadata, not output content |

### 4b. Truth function — Shape 2 locked

```python
@property
def font_preserved(self) -> bool:
    return not self.font_substituted and not any(
        d.kind in FONT_AFFECTING_KINDS for d in self.degradations
    )
```

**Reasoning for Shape 2 over Shape 1.** `font_substituted` is honest today
(architecture-analysis-confirmed across all 4 substitution sites via
`substitution_log` plumbing in v0.1.2 — INV-C-4). Folding it into
`degradations` as a new `font_substituted_fallback` kind (Shape 1) creates
two-source-of-truth schema duplication for one release with no clean
migration path until v0.2 removes the old field. Shape 2 keeps
`font_substituted` as a separate input — caller has two fields to think about,
but each is single-purpose and INV-K-3 (signature superset) is preserved
without churn.

### 4c. `dry_run` ↔ `degradations` contract

> **The `degradations` list produced by `dry_run=True` is identical to the
> `degradations` list produced by `dry_run=False` against the same input.**

- **Enforcement layer:** engine. Every degradation append occurs *before* the
  `if not dry_run: pdf.save(...)` branch in `surgeon._apply_single_replacement`,
  `reflow.reflow_paragraph`, and `structural.replace_block`. Bridge layer
  (`pdf-edit-mcp/bridge.py`) serializes whatever the engine returns; no
  enforcement responsibility there.
- **Test approach:** parametrized test in `tests/invariants/test_e_1_dry_run_preserves_bytes.py`
  (or a sibling J-layer probe) that runs each of N representative inputs
  twice — once with `dry_run=True`, once `dry_run=False` — and asserts
  `result_a.fidelity_report.degradations == result_b.fidelity_report.degradations`
  using `Degradation.__eq__` (frozen dataclass, structural equality).
- **Failure mode protected against:** code paths that only emit `Degradation`
  *after* writing the final PDF — those would fail the contract because
  `dry_run=True` skips the write. The implementation prompt must restructure
  any such path to emit during planning, not during commit. The four
  failure-return paths (rows 2, 3, 5, 6) already emit before any write happens
  (they short-circuit on `success=False`); the success paths must be
  audited to ensure the same.

## §5 Invariant inventory

### Existing invariants v0.1.3 touches

**`INV-J-3`** (verbatim from `docs/decisions.md` row 17, dated 2026-04-25):

> `EditResult.__post_init__` enforces overflow contract at the dataclass
> boundary — INV-J-3: when `overflow_detected=True`, an "overflow" warning
> is auto-appended if absent.

**Assessment:** *preserved*. v0.1.3's `Degradation` for `overflow_shift_clamped`
is additive and never sets `overflow_detected` directly — the flag's
semantics and the warnings invariant are untouched.

**`INV-K-3`** (verbatim from `docs/ultimate-audit-charter.md:258–262`):

> Signature compatibility: for each function in `__all__`, its current
> signature is a superset of the v0.1.1 signature (only new parameters with
> defaults). Import the package from `pdf_edit_engine==0.1.1` in a sibling
> venv, compare `inspect.signature`. *Lead-direct.*

**Assessment:** *preserved*. The new `degradations: list[Degradation] =
field(default_factory=list)` on `FidelityReport` is additive with a default,
and `Degradation` itself is a new public type — neither changes any existing
function signature.

**`INV-J-1`, `INV-J-2`, `INV-J-4`** (from charter §J):

> J-1: every `EditResult` returned from every public edit function has a
> `fidelity_report` attribute of type `FidelityReport`.
> J-2: `font_action == "extended"` implies at least one of
> `font_preserved==True`, `glyphs_missing==[]`, `overflow_detected` is
> explicitly set.
> J-4: `success == False` implies `font_action == "failed"` OR `warnings` is
> non-empty. Never success=False without a reason.

**Assessment:**
- J-1 *preserved* — `FidelityReport` keeps every existing field.
- J-2 needs **re-check** — when v0.1.3 flips `font_preserved=False` on the
  4 lying paths AND `font_action` was `"failed"` (not `"extended"`), J-2 is
  vacuously satisfied. When `font_action="extended"` and the new
  computed-property returns `False` because of a `font_extension_failed`
  degradation, J-2's three-of-three disjunction must still hold —
  `glyphs_missing` is still populated on these paths, so `glyphs_missing==[]`
  is false, but `overflow_detected` and `font_preserved` are both false too.
  The original J-2 wording is `font_preserved==True OR glyphs_missing==[] OR
  overflow_detected_set`. After v0.1.3 these three remain individually
  evaluable; the implementation prompt must verify J-2 still passes on
  representative paths.
- J-4 *preserved* — every `success=False` path adds either an existing
  warning or a `Degradation` (which the bundled implementation extends to
  also append a corresponding warning, preserving J-4's `warnings non-empty`
  guarantee).

### New invariants introduced by v0.1.3

**`INV-J-5`** (replaces architecture-analysis-proposed `INV-D-1`):

> Every code path that emits an `EditResult` for a degraded result appends a
> typed `Degradation` to `EditResult.fidelity_report.degradations` before
> returning.

**`INV-J-8`**:

> `FidelityReport.font_preserved` is a computed property derived from
> `degradations` (none of kind in `FONT_AFFECTING_KINDS`) AND
> `font_substituted` is `None`; never hardcoded.

The kerning algorithm choice (§1) and detector signal (§2) are documented as
algorithm specs in their respective sections, NOT as freestanding invariants.
Project culture (per `decisions.md`) reserves invariants for cross-cutting
contract claims.

## §6 Probe pattern documentation

### Exemplar — `tests/invariants/test_d_3_get_text_deterministic.py`

```python
"""INV-D-3: get_text(pdf) is deterministic — two calls produce byte-identical strings."""

from __future__ import annotations

from pathlib import Path

import pytest

from pdf_edit_engine import get_text

CORPUS_DIR = Path(__file__).parent.parent / "corpus"

CANDIDATES = [
    "reportlab_simple.pdf",
    "cidfont_synthetic.pdf",
    "chrome_webpage.pdf",
    "Aryan_BV_Resume_2026.pdf",
    "gdocs_document.pdf",
]


@pytest.mark.parametrize("name", CANDIDATES)
def test_inv_d_3_get_text_deterministic(name: str) -> None:
    """get_text(pdf) is deterministic — two calls produce byte-identical strings."""
    path = CORPUS_DIR / name
    if not path.exists():
        pytest.skip(f"corpus file {name} not present")
    a = get_text(str(path))
    b = get_text(str(path))
    assert a == b, f"{name}: get_text non-deterministic; lengths {len(a)} vs {len(b)}"
```

### Conventions (extracted from this exemplar + 75 sibling probes)

- **Filename:** `test_<lowercase-id>_<topic>.py` (e.g.
  `test_d_3_get_text_deterministic.py`, `test_j_3_overflow_implies_warning.py`).
- **Module docstring:** one-line invariant statement, prefixed with the ID.
- **Imports:** `from __future__ import annotations`; `pathlib.Path`; `pytest`;
  the engine's public function under test.
- **Fixture base:** `Path(__file__).parent.parent / "corpus"` (constant
  `CORPUS_DIR`).
- **Skip on missing fixture:** `pytest.skip(f"corpus file {name} not present")`
  — corpus files may be gitignored on contributor machines.
- **Parametrization:** `@pytest.mark.parametrize` with serializable values
  (strings, tuples), one row per case.
- **Assertion message:** describes the violation precisely; includes
  observed vs. expected so the failure log is actionable.

### `INV-J-5` probe sketch

The probe is parametrized **per code path** (not per `kind`), per the
architecture analysis: "every CODE PATH emitting a degradation, not every
kind being emittable." Parameter rows draw from the broader ~19-site
degradation surface (§3 final paragraph + the architecture analysis's site
list).

**Parameter shape** (pytest-serializable):

```python
SiteCase = NamedTuple("SiteCase", [
    ("site_id", str),               # e.g. "surgeon_271_kerning_compressed"
    ("expected_kind", str),         # one of the 10 locked kinds
    ("expected_severity", str),     # "info" | "warning" | "error"
    ("fixture_id", str),            # key into FIXTURE_FACTORIES below
    ("edit_args", str),             # JSON-encoded args for replace/replace_block
])
```

**Fixture factory dict:**

```python
FIXTURE_FACTORIES: dict[str, Callable[[Path], Path]] = {
    "sow_word_winansi": _build_sow_winansi,
    "synth_identity_h_kern_overflow": _build_synth_identity_h_kern_overflow,
    "synth_table_4cell_merge": _build_synth_table_4cell,
    "synth_heading_font_dropped": _build_synth_heading_font_dropped,
    "synth_overflow_shift_suppressed": _build_synth_overflow_shift,
    # ... per-site factories ...
}
```

Sites with a natural fixture (kerning compression on SOW; detector signal on
SOW Deliverables; font_extension_failed on a Calibri PDF asked for an unknown
glyph) use string keys pointing at corpus PDFs. Sites without a natural
fixture (low-level `OperatorError` paths) use synthetic-content-stream
factories that emit a minimal pikepdf PDF triggering exactly that code path —
those factories live in a sibling module
`tests/invariants/_degradation_fixtures.py`.

**Test body:**

```python
@pytest.mark.parametrize("case", DEGRADATION_SITES, ids=lambda c: c.site_id)
def test_inv_j_5_degradation_surfacing(case: SiteCase, tmp_path: Path) -> None:
    """INV-J-5: every degraded code path appends a typed Degradation."""
    factory = FIXTURE_FACTORIES[case.fixture_id]
    fixture = factory(tmp_path)
    args = json.loads(case.edit_args)
    out = tmp_path / "out.pdf"
    result = _dispatch_edit(fixture, out, args)  # calls replace/replace_block/etc.
    kinds = [d.kind for d in result.fidelity_report.degradations]
    severities = [d.severity for d in result.fidelity_report.degradations]
    assert case.expected_kind in kinds, (
        f"{case.site_id}: expected kind {case.expected_kind!r} not in "
        f"degradations {kinds!r}"
    )
    matched = next(
        d for d in result.fidelity_report.degradations
        if d.kind == case.expected_kind
    )
    assert matched.severity == case.expected_severity, (
        f"{case.site_id}: kind={case.expected_kind} expected severity "
        f"{case.expected_severity!r}, got {matched.severity!r}"
    )
```

The `DEGRADATION_SITES` list is the parametrize source — one `SiteCase` per
the ~19 emission sites. Each site's `expected_kind` and `expected_severity`
come from the §3 mapping table (for the 11 `font_preserved` sites) plus the
broader emission-site-to-kind map worked out during implementation against
the architecture analysis's site list.

### Probe scope

The probe verifies INV-J-5 *site-by-site* — which is correct because the
invariant is about every code path emitting a degradation, not about every
kind being emittable from at least one path. Coverage of all 10 kinds emerges
naturally from covering every site that emits each kind.
