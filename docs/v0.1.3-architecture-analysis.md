# v0.1.3 Architectural Analysis

> Read-only diagnosis commissioned by `.claude/prompt.md`. Two findings from the
> M10 demo (2026-05-04) prompted it: (1) `"Sarah Chen" → "Søren Müller"` in a Word
> A4 SOW shipped with visible glyph collisions while `FidelityReport` claimed full
> fidelity; (2) the engine's default `reflow=True` silently merges paragraphs across
> table-cell layouts, forcing the demo to set `reflow=False` for every variant. The
> hypothesis to test: both findings are instances of one architectural failure
> class. This analysis tests it with falsification first, then commits to one
> position with v0.1.3 vs v0.2 scoping resolved.

## Decision points

Five branches in surgeon / reflow / structural where v0.1.2 chooses to emit a
degraded result rather than refuse, and where the typed `FidelityReport` does not
describe what happened. The list is bounded by materiality, not breadth — five
distinct points cover four module surfaces (kerning math, paragraph detection,
font-extension failure, structural overflow) without double-counting. Adding a
sixth (the heading/marker palette drop in `structural.py:1042–1063`) is mechanism-
redundant with #4 below.

| # | File:line | Trigger | Output | FidelityReport says | Doc claim | Confidence |
|---|---|---|---|---|---|---|
| 1 | `surgeon.py:271–274` | `abs(total_kern) > 0.5 * original_fu` | flat unkerned `pikepdf.String` (collisions visible) | `font_preserved=True`, `overflow=False`, `glyphs_missing=[]` — no field describes the squash | README l.49: "all characters rendered" — silent on collision | **HIGH** (M10 mechanism, traced through `_apply_single_replacement` → `_modify_tj_operator`) |
| 2 | `reflow.py:312–382` (`_detect_paragraphs_from_index`) | y-cluster + font + x-jump check; no table-cell signal | one paragraph spanning two table cells; `reflow_paragraph` then re-renders the merged paragraph as one BT/ET block | `reflow_applied=True`, `overflow_detected=False` if shifts fit | LIMITATIONS.md l.5 covers "cross-paragraph reflow" only — does not apply when the engine *merged* two cells into one paragraph | **HIGH** (mechanism traced; the table-cell layout is structurally indistinguishable from a multi-line bullet to this detector) |
| 3 | `surgeon.py:569–602` | `extend_subset` raises `FontNotFoundError` / `PDFEditError` | `success=False` returned — but with `font_preserved=True` | `font_preserved=True` despite no font being preserved (the operation didn't run) | README l.46: `font_preserved=True` "original font kept" — outright wrong on this path | **HIGH** (failure-path lie; pure contract bug) |
| 4 | `reflow.py:738–743` | heading font cannot encode replacement first line | render in body font instead; comment "Graceful degradation" | no field; comment is the only signal | docs silent | **MEDIUM** (correct mechanism, rarely fires; needs non-body heading font + non-Latin replacement) |
| 5 | `structural.py:1182–1185` | `text_height > available_height` after shift clamp | `line_height` divided down to fit (cramped) | no field; only surfaces if shift produced a `warning` | LIMITATIONS / README silent | **MEDIUM** (fires on bbox edits with overflow; cramping is bbox-bound but caller has no machine-readable signal) |

**End-of-phase finding.** *All five branches share the structural property of
producing a visually-degraded or contract-violating result without populating any
typed `FidelityReport` field that callers can branch on; the only signals are
textual `warnings` (line #5 partially) or English source comments (line #4).*

## FidelityReport contract

For each field of `FidelityReport` (`models.py:59–66`): set sites, condition, doc
claim, caller branching, divergence.

- **`font_preserved`.** Set in 13 sites across the engine. **11 hardcode `True`**;
  only `structural.py:1252–1267` computes it dynamically (`font_action=="kept" and
  not font_switched and not substitution_log`). README l.46 + the MCP wrapper's
  README l.28–32 advertise it as the visual-fidelity gate. Callers branch on it
  at `pdf-edit-mcp/bridge.py:215, 294`. **Divergence: lies on every kerning-
  compressed success path AND on every failure-return path.**
- **`font_substituted`.** ARY-281 substitution_log out-parameter, honored
  consistently across surgeon / reflow / structural via
  `substitution_log[0] if substitution_log else None`. Caller branching:
  `bridge.py:300`. **Honest.**
- **`overflow_detected`.** Surgeon's check is page-edge-only
  (`match.bounding_box[0] + new_width > page_width`); reflow's is
  `extra_lines > 0`; structural's is `text_height > bbox_height`. Same field
  carries three different definitions across entry points; INV-J-3
  (`models.py:88–97`) backstops only the warnings invariant.
  **Partially honest: the field name papers over three semantically-distinct
  conditions.**
- **`reflow_applied`.** Set `True` only when `reflow_paragraph` actually
  completed. **Honest** on its own path — but mute on the silent fallback at
  `surgeon.py:1067–1071`, where reflow is *attempted*, raises `ReflowError`,
  is caught, and the path returns through `_apply_single_replacement` whose
  constructor hardcodes `reflow_applied=False`. Caller cannot distinguish
  "never tried" from "tried and aborted."
- **`glyphs_missing`.** Honest on failure-return paths (carries the resolver's
  `missing` list). Always `[]` on success even when kerning compression
  squashed every glyph. **Partially honest** — name implies "characters that
  won't render," reality is "characters not encoded by the font."

**End-of-phase finding.** *The contract is partially honest:
`font_substituted` and `reflow_applied` honor their stated semantics,
`overflow_detected` honors its with three different definitions across entry
points, and `font_preserved` and `glyphs_missing` are systematically misleading —
`font_preserved` lies on every degraded-success and every failure path, and
`glyphs_missing` describes encoding gaps, not visual rendering quality.*

## Verdict: two algorithm bugs + one observability gap

**The genuine counter-hypothesis.** *"These are two unrelated algorithm bugs. The
kerning bug is wrong fallback math: change `_encode_with_kerning:271–274` so the
> 0.5×original_fu branch uses horizontal text-space scaling (`Tz` operator) or
per-glyph compression rather than dropping to a flat unkerned string. The
reflow-across-cells bug is wrong paragraph detection: add a table-cell signal to
`_detect_paragraphs_from_index:312–382` (consecutive same-y elements with
regular x-grid spacing). Fix both at the algorithm layer; `FidelityReport`
doesn't need to change. There is no architectural class — there is a kerning
bug and a detector bug."*

**Where it's correct.** Mostly. Each visible bug *is* an algorithm bug at root.
Neither requires a `FidelityReport` schema change to be *fixed*. A v0.1.3 that
ships only the algorithm fixes would close the two M10 failures.

**Where it's incomplete.** It would still leave latent silent-degradation
behaviors that did not happen to fire in the M10 demo:

- `surgeon.py:576, 596` — `font_preserved=True` returned alongside
  `success=False`. Pure contract bug; no algorithm fix removes it.
- `reflow.py:738–743` — heading-font drop is intentional behavior. Refusing
  would break flows the engine supports today; the only fix is *surface*, not
  *change*.
- `structural.py:1182–1185` — line-height compression *is* the right algorithm;
  cram-to-fit is the caller's request. The defect is the caller cannot tell.

**The honest verdict.** **These are two algorithmically-distinct bugs with a
shared failure mode at the reporting layer.** The kerning bug and the reflow-
across-cells bug have nothing in common at the algorithm or call-surface level.
They share exactly one thing: each produced an `EditResult.fidelity_report` whose
typed fields said "fine" while the rendered output said "broken." **The fix is
per-bug at the algorithm layer plus a single observability change at the report
layer — not an architectural redesign.**

This matters for scope. Calling this "one architectural class" justifies a
unified rewrite. Calling it correctly justifies three small independent fixes:

| Fix | Layer | Owner ticket | This analysis commits to |
|---|---|---|---|
| Kerning math: replace flat-fallback at > 0.5× | algorithm (surgeon) | ARY-290 (proposed) | identifies, defers code |
| Table-aware paragraph detection | algorithm (reflow) | ARY-292 (proposed) | identifies, defers code |
| `FidelityReport.degradations` typed field | observability (models + 13 append sites) | this analysis | **commits in Phase 4** |

**End-of-phase finding (the loud one).** *There is no single failure class. The
kerning compression and reflow-across-cells findings are two algorithmically-
distinct bugs sharing one failure mode at the reporting layer. The fix is per-
bug at the algorithm layer plus one observability change at the report layer —
not an architectural redesign.*

## Proposal: the observability fix only

Algorithm fixes ARY-290 and ARY-292 are **out of scope for this deliverable**.
This proposal commits only to the observability change.

**Schema (additive).** `models.py` gains a frozen `Degradation` dataclass with
`kind: Literal["kerning_compressed", "kerning_widened", "heading_font_dropped",
"marker_font_dropped", "line_height_compressed", "overflow_shift_clamped",
"overflow_shift_suppressed", "reflow_aborted_to_simple", "font_extension_failed",
"paragraph_detection_low_confidence"]`, optional `detail: str | None`, and
`severity: Literal["info", "warning"]`. `FidelityReport` gains
`degradations: list[Degradation] = field(default_factory=list)`. Default empty;
INV-K-3 (superset-compatible signatures) preserved.

**Behavior policy unchanged.** The engine continues to *emit* a degraded result
rather than refuse. Refusing by default would break the MCP wrapper and every
agent flow. What changes: each degradation site appends a typed `Degradation`.
Agents that want refuse-on-degradation gate on
`if r.fidelity_report.degradations: skip()`.

**`font_preserved` — failure-path lies fixed; success-path lies kept.**
`surgeon.py:576, 596` and `reflow.py:959, 979` set `font_preserved=False` in
v0.1.3 (those four sites return `success=False`; callers gate on `success`, so
this is a bug fix, not a behavior change). Success-path `font_preserved=True`
when kerning compression fires stays; README adds the explicit redirect:
`degradations` is the visual-fidelity gate. Changing success-path semantics
would break `tests/test_surgeon.py:87–96` and the MCP-advertised contract;
deferred to v0.2 with a `font_preserved_strict` computed alias.

**Reflow-across-cells: surfacing only.** When `_detect_paragraphs_from_index`
builds a paragraph crossing > 1 visual column (x-jump > 50pt or width > 60% of
inferred page width with no bullet pattern), append
`Degradation(kind="paragraph_detection_low_confidence", ...)`. Detector
improvement is ARY-292.

**Aggregation (`replace_all` / `batch_replace`).** Per-result `degradations`
ride in the existing `list[EditResult]` — no engine-side flattening. The MCP
aggregator at `pdf-edit-mcp/bridge.py:290–303` adds two fields: `degradations_
present: bool` and `degradation_kinds: sorted list[str]` (dedup by kind, not
detail — agents care that something fired). Existing `font_preserved=all(...)`,
`overflow_detected=any(...)` aggregators stay.

**`dry_run=True`.** Populates `degradations` identically to a real run. Every
append must occur before the `if not dry_run: write` check. This is the agent-
preview value of `dry_run` — verified by one parametrise row in T1 below that
runs the same fixture twice and asserts identical `degradations` lists.

**INV-D-1 (new structural invariant).** *Every code path that emits a degraded
result must append a typed `Degradation` to the `EditResult` before returning.*
Enforced by one parametrised probe `tests/invariants/test_d_1_degradation_
surfacing.py` — one row per known degradation site, not 13 separate tests.
Matches the audit-charter "probes not reading" pattern.

**Realistic scope (engine + MCP, ~225–250 LOC, 8 files):**
`models.py` ~30 LOC (M1–M3); `surgeon.py` ~25 LOC (S1–S5: appends at 271, 257,
569, 1067; failure-path `font_preserved=False` at 576, 596); `reflow.py` ~35 LOC
(R1–R6: appends at 738, 953, 973, 1037, 312; failure-path lies at 959, 979);
`structural.py` ~20 LOC (ST1–ST5: appends at 1042, 1054, 1182, 1153; thread into
1255 constructor); `pdf-edit-mcp/bridge.py` ~15 LOC (B1–B4: serializer at 207,
aggregator at 290, engine pin at 1430 → `>=0.1.3`); `pdf-edit-mcp/src/{constants,
index,schemas}.ts` ~15 LOC; new probe `tests/invariants/test_d_1_degradation_
surfacing.py` ~80 LOC; README + LIMITATIONS + decisions + mcp/README ~30 LOC.

**Migration.** Engine v0.1.2 → **v0.1.3 (PATCH)**; pdf-edit-mcp v0.1.0 →
**v0.2.0 (MINOR)**; ship together per Linear doc 10 §F. The MCP version pin
already gates older engines (`bridge.py:1430` exits FATAL on engine < 0.1.3
after the bump), so no mixed-version footgun.

### Scoping: v0.1.3, not v0.2

**v0.1.3.** Three reasons. (1) The schema change is additive at the engine
boundary — INV-K-3 preserved; that is what `0.1.x` is for. (2) The known instances
(5 from Phase 1 + 11 hardcoded `font_preserved=True` sites + 3 semantic-overload
under `overflow_detected`) ship to PyPI today and the marketing launch shipped
2026-05-02; deferring to v0.2 (months out per Linear doc 10) leaves a multi-month
window of known silent degradation in the launch's blast radius. (3) v0.2's
session API and plan/apply/verify *compose with* `degradations` — the proposed
v0.2 `ConfidenceReport` reads it instead of re-deriving its own taxonomy. Doing
this in v0.1.3 de-risks v0.2.

**Stopgap if deferred.** The minimal launch-unblocker is a README + LIMITATIONS
edit that documents the success-path lie and the kerning-compression / reflow-
across-cells failure modes. ~30 LOC of docs. Buys time at the cost of shipping
the same launch with a known-broken contract.

### Red team

**Objection 1 — duplicates `warnings`.** `warnings` is `list[str]` for human
reading; `degradations` is `list[Degradation]` with a `Literal[...]` `kind` for
machine branching. INV-J-3's `overflow ⇒ warning` rule still governs human-
facing strings. *Invalidates if:* no MCP agent branches on `kind` within 30 days
post-launch — then the field is dead weight.

**Objection 2 — too much for a patch window.** The probe is one parametrised
test, not 13. Per-site appends are ~5 LOC each. ARY-281's substitution_log
shipped this exact pattern across 4 sites in a single session. *Invalidates if:*
site-by-site work uncovers a degradation case not catalogued here (e.g. locator-
side); stop-and-rescope rule pre-committed.

**Objection 3 — surfacing without algorithm fixes makes silent breakage into
visible breakage.** Visible breakage is the precondition for agent gating: skip,
retry with `reflow=False`, escalate. Without the field, no signal exists and
degraded outputs ship blindly. ARY-290 / ARY-292 close the breakage; this
proposal bounds the blast radius until they land. *Invalidates if:* no MCP
agent actually gates on `degradations` (mitigation: extend the existing
fidelity-inspection language in `pdf-edit-mcp/src/index.ts:1326–1401` to
`degradations` — one line per tool).

### Plain-language summary

The engine quietly makes "good-enough" choices when the perfect edit is not
possible — squashing letters together to fit, dropping a heading font, cramming
lines closer together. The report it returns currently says the edit succeeded
with full fidelity. Two of these choices caused the M10 demo to ship visibly
broken pixels. The fix is to add one new field to the report — a typed list of
every "good-enough" choice the engine actually made — so calling code can see
which choices fired and decide whether to accept them. The engine still makes
those choices (refusing by default would break every existing user); it just
stops being silent about them. Patch release on the engine; minor version bump
on the MCP wrapper to surface the new field; no public-API breaks.

## Open questions

1. **Trigger calibration for `paragraph_detection_low_confidence`.** The
   proposed gate (x-jump > 50pt, or paragraph width > 60% of inferred page width
   with no bullet pattern) needs measurement against the existing Chrome /
   Word / reportlab / pikepdf-synthetic fixtures: false-positive rate must stay
   under ~5% or agents will treat the signal as noise. To resolve before merge:
   run the gate against the four corpora and tabulate true / false positives.
2. **MCP v0.2 aggregation reshape.** Whether `degradations` aggregation in the
   MCP wrapper should evolve to `dict[kind, count]` for the v0.2 session API.
   Defer to v0.2 design doc.
3. **Algorithm-fix bundling.** Whether ARY-290 (kerning math) and ARY-292
   (table-aware detector) bundle into v0.1.3 or land in v0.1.4. Maintainer
   call; not blocking the observability fix.
